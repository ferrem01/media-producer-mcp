Media Producer MCP

Architecture, pipelines, and concepts

System Overview

Media Producer MCP is an AI-powered video/image production server. It takes a text prompt, plans a storyboard, generates visual scenes via LLM codegen, assembles them into HTML+GSAP documents, captures frames via Playwright, and encodes the final video with ffmpeg.

MCP Protocol

Generate Pipeline

The generate pipeline transforms a user prompt into a complete project with scenes, components, and timing. It runs as a queued background job. All scenes go through the same unified codegen path.

1. Prompt Expansion expander.ts
Detects thin prompts and expands them into rich creative briefs. Rich prompts pass through unchanged. Ensures the planner always has enough detail to work with.
2. Creative Direction concept-director.ts
Generates 3 distinct creative concepts, self-critiques them, picks the strongest. Outputs a "creative bible" with the big idea, storytelling pattern, visual through-line, emotional arc, and key visual commitments. The CreativeBible is passed as structured data through the entire pipeline and saved to project.creative_bible.
3. Storyboard Planning unified-planner.ts
The single planner used by all generate modes (plan, generate, full). Plans the full storyboard: writes a rich visual brief per scene, sets timing, transitions, and voiceover scripts. Receives the component catalog so it can guide the codegen LLM toward library components. The storyboard is saved to project.storyboard for plan mode review.
4. Scene Generation scene-generator.ts
Unified codegen pipeline for every scene:

1. buildCodegenBrief() — assembles the scene brief, creative bible, brand kit, and component catalog into a codegen prompt.
2. Freeform-agentic multi-turn LLM — generates HTML+CSS+GSAP with access to tools: search_library (find components), read_source (read component/template source), and submit_scene (deliver final output).
3. <component> tag resolution — the assembler resolves any <component type="..." data='...' /> tags in the LLM output to real component HTML/CSS/JS at render time.

The LLM can write fully custom HTML, embed library components via <component> tags, or mix both in a single scene.
5. Visual Critique critiquer.ts / multi-pass-critiquer.ts
Renders a preview frame of each scene, sends it to a vision model for evaluation. Scores the scene and suggests revisions. Multi-pass critique uses contact sheets (6 frames across the timeline) for motion evaluation. Scenes below threshold get revised.
6. Media Enrichment media-enrichment.ts / image-enrichment.ts
Enriches scenes with stock footage (Pexels API), AI-generated images (DALL-E/others), and asset references. Replaces placeholder images with real content.
7. Audio Generation scene-voiceover.ts / music.ts
Generates TTS voiceover per scene from voiceover_text. Selects background music. Builds audio mix with ducking (voice up, music down during speech).
8. Save Project persistence/project.ts
Writes project.json with all scenes, components, timing, audio tracks, and metadata. The project is now ready for the render pipeline.

Render Pipeline

The render pipeline takes a saved project.json and produces the final output file (MP4, GIF, PNG, or PDF). It runs as a queued background job with parallel scene rendering.

1. Scene Assembly scene-assembler.ts
Each scene's codegen HTML is assembled into a self-contained document. Brand kit becomes CSS variables, any <component> tags are resolved to real component HTML/CSS/JS, and GSAP scripts build a master timeline. The assembler handles both fully custom HTML and component-embedded scenes uniformly.
2. Frame Capture capture.ts / capture-worker.ts
Playwright loads the assembled HTML, steps through the GSAP timeline frame-by-frame (at the project FPS), and screenshots each frame as PNG. Runs in a worker process. Scenes render in parallel (concurrency: 2).
3. Scene Encoding encode.ts
ffmpeg encodes each scene's frames into an MP4 segment (H.264). Quality settings, resolution, and frame rate come from the project canvas.
4. Transitions transitions.ts
Between-scene transitions are rendered as mini HTML scenes. Extract last frame of scene A and first frame of scene B, composite them with a GSAP animation (crossfade, slide, zoom, shader effects), capture, and encode.

30+ transition types including WebGL shader transitions (crosswarp, ripple, radial, chromatic).
5. Concatenation encode.ts
ffmpeg concatenates all scene segments and transition segments into one continuous video. The concat filter handles different durations seamlessly.
6. Audio Mix mixer.ts
Mixes voiceover, music, and SFX tracks onto the video. Applies ducking (music volume drops during speech) and fade in/out. Outputs the final output.mp4.

Unified Codegen

Every scene is generated through a single codegen pipeline. The LLM writes full HTML+CSS+GSAP for each scene and can embed library components via <component> tags. Multi-beat choreography is expressed directly in GSAP timeline code.

🎞️ Scene

The fundamental unit of a video. Each scene is a self-contained HTML+CSS+GSAP document produced by the codegen LLM.

  • Full HTML document with embedded styles and scripts
  • GSAP master timeline controls all animation
  • Can mix custom HTML with <component> tags
  • Typically 3-30 seconds depending on complexity
  • Connected by between-scene transitions
scene-assembler.ts

🧩 <component> Tags

The LLM can embed library components in its HTML output using self-closing tags. The assembler resolves these to real component HTML/CSS/JS at render time.

  • <component type="stat-card" data='{"value":"10M"}' />
  • Resolved by the assembler before frame capture
  • Component styles are auto-scoped per instance
  • Component timelines wire into the master timeline
  • Mix freely with custom HTML in the same scene
component-parser.ts

How Multi-Beat Scenes Work

Complex choreography (product walkthroughs, multi-step demos) is expressed directly in GSAP timeline code by the LLM. The LLM writes labeled timeline sections that enter, move, and exit elements at choreographed times.

3 library components orchestrated via GSAP timeline labels, 24 seconds total

Codegen Output Structure

📝 Planner Brief

The unified planner writes a rich visual brief per scene: what the viewer experiences, which library components to consider, motion descriptions, and timing. This brief drives the codegen LLM.

🤖 LLM Codegen

The freeform-agentic LLM reads the brief, searches the component library, reads component/template source code for reference, then writes complete HTML+CSS+GSAP. It can use <component> tags for library components or write everything from scratch.

🏗️ Assembler Resolution

At render time, the assembler parses the codegen HTML, finds <component> tags, resolves each to real component HTML/CSS/JS, scopes styles, and wires component timelines into the master GSAP timeline.

Component Library

67 reusable HTML+CSS+GSAP animation components. Each is a self-contained .component.html file with a template section (HTML), style section (CSS), and script section (JS with createTimeline function). Components are data-driven via template binding and embeddable via <component> tags.

Component Anatomy

📦 .component.html

Three sections in one file:

  • <template> -- HTML structure with {{variable}} bindings
  • <style> -- Scoped CSS (auto-prefixed per instance)
  • <script> -- createTimeline(el, data, ctx) returns a GSAP timeline

The assembler parses these, binds data, scopes styles, and wires timelines into the master GSAP timeline.

The unified planner writes a rich freeform_brief for each scene. This includes what the viewer experiences, suggested library components, motion descriptions, timing, and visual style guidance from the CreativeBible.

📦 2. Build Codegen Brief

buildCodegenBrief() assembles the full context for the LLM: the scene's visual brief, the CreativeBible's visual style constraints, the brand kit (colors, fonts, logos), canvas dimensions, and the component catalog so the LLM knows what's available.

File: scene-generator.ts
Inputs: PlannedScene + CreativeBible + BrandKit + Canvas + ComponentCatalog

🤖 3. Freeform-Agentic LLM

Multi-turn LLM conversation with tool access. The LLM can explore the component library, read component and template source code for reference, then write complete HTML+CSS+GSAP. It delivers the final scene via submit_scene.

Available tools:
  search_library — search the 67-component catalog by keyword
  read_source — read a component or template's full source code
  submit_scene — deliver the final HTML+CSS+GSAP output
Agentic LLM (multi-turn)
Highest creative ceiling

🏗️ 4. Component Tag Resolution

The assembler scans the LLM's HTML output for <component> tags and resolves each one: loads the component's .component.html, binds the data attributes, scopes CSS, and injects the component's createTimeline() into the master GSAP timeline.

Input: HTML with <component type="stat-card" data='{"value":"10M"}' />
Output: Final self-contained HTML document ready for frame capture

How Library Components Are Used

Library components are embedded directly in codegen output via <component> tags. The LLM decides when to use them:

  • Pure custom: The LLM writes all HTML/CSS/GSAP from scratch. No component tags.
  • Component-heavy: The LLM uses multiple <component> tags with custom GSAP to orchestrate them (e.g., product walkthroughs with quotient-chat, canva-editor, etc.)
  • Hybrid: Mix of custom HTML and component tags in the same scene (e.g., custom layout wrapping library stat-cards).

The planner's brief guides the LLM toward using library components when they're appropriate, or writing custom code when the scene needs something unique.

Data Model

Projects are stored as JSON with associated file assets on disk. Multi-tenant architecture with tenant isolation.

File Structure

/data/media-producer/
  └── {tenant-id}/
      ├── brand-kit/
      │   ├── brand-kit.json
      │   └── assets/ (logos, fonts)
      ├── components/ (tenant-specific components)
      └── projects/
          └── proj_{id}/
              ├── project.json
              ├── components/ (codegen HTML files)
              ├── _work/
              │   ├── scene_0/ (frames, scene.html, scene.mp4)
              │   ├── scene_1/
              │   ├── transition_0_1/
              │   └── ...
              └── output/
                  └── output.mp4

Project JSON Shape

📋 Project

  • project_id -- unique identifier
  • tenant_id -- tenant isolation
  • name -- display name
  • format -- video | image | gif | presentation
  • canvas -- width, height, fps, preset, background
  • brand_kit -- colors, fonts, logos
  • creative_bible -- concept, pattern, visual style
  • storyboard -- PlannedScene[] from planner
  • scenes[] -- ordered scene list
  • audio -- track list + ducking config

🎞️ Scene

  • id -- scene identifier
  • label -- display name
  • duration_seconds
  • html -- codegen HTML output
  • transition_in -- entry transition
  • background -- color or gradient
  • voiceover_text

🧩 SceneComponent

  • id -- instance id (comp_0, comp_1...)
  • type -- component type name
  • data -- template binding data
  • z_index -- layer order
  • position -- x, y, width, height (%)

🎨 BrandKit

  • colors -- primary, accent, background, text
  • fonts -- heading, body (Google Fonts)
  • logos -- primary, secondary, icon
  • name -- brand name
